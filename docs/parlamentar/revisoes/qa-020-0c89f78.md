### P2-E: o filtro de URLs agora corta o resto da mensagem, não só a query (regressão do delta, só diagnóstico)

- **Código:** `src/leis_mcp/catalog/snapshot.py:55`. A regex nova `_QUERY = r"((?:https?://|/)[^\s'\"?#]*)[?#][^'\"]*"` consome, depois de `?` ou `#`, tudo até a próxima aspa ou o fim da linha, **inclusive espaços**. A anterior parava no espaço. Também passou a casar qualquer `/…?` ou `/…#`, mesmo fora de URL.
- **Reprodução** (`scrub_urls` direto; e log real `debug-update-0c89f78.log`):
  - `'GitError: … fatal: path a/b?c not found; retrying later with more details'` vira `'GitError: … fatal: path a/b'`;
  - `'Erro em federal/leis#123: depois deste ponto vem texto importante'` vira `'Erro em federal/leis'`;
  - `'HTTPS://H/P?SIG=X rest of message'` vira `'HTTPS://H/P'`;
  - no log real do httpx, `…/f3408ddf-…"HTTP/1.1 200 OK"` fica sem o espaço antes do status.
- **Esperado:** remover só a query e o fragmento da URL. **Atual:** o texto de diagnóstico depois da URL some. Isso vale nos loggers httpx/httpcore e na linha `Index preparation failed` do provider (`provider.py:89`). Não vaza nada; erra para o lado da redação. Mas o log de falha do git ou do snapshot pode perder a causa. Uma correção possível é parar a query em espaço, salvo quando a URL estiver entre aspas, e cobrir os exemplos acima em `test_url_scrubbing`.

### P2-G: falha transitória do snapshot no `update` agora dispara clone e build completos pelo git

- **Código:** `cli.py:134-140`. Qualquer `SnapshotError` que não seja de orçamento leva ao git, inclusive `ConnectError` (DNS ou rede), HTTP 5xx e TLS recusado. Reproduzido com o 404 do manifesto (cenário C). O caso de 5xx e de rede segue a mesma linha (`snapshot.py:458-460`, `:599-601`).
- **Efeito:** num home instalado só por snapshot, sem clone (usuário 0.2.0 típico), um 500 passageiro do GitHub faz o `update` clonar e montar tudo localmente. No Fly, onde o clone já existe, é o mesmo trabalho que a rotina 0.1.0 já fazia toda semana. Se a rede estiver fora, o git falha também e sai com exit 2. É coerente com o desenho, mas o `operacao.md` lista só "manifesto ausente, 404, arquivo corrompido ou índice recusado". Sugiro acrescentar "erro de rede ou HTTP do publicador" para o operador não se surpreender.
